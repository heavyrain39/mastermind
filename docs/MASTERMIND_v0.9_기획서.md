## 3. 이번 작업 상세 (v0.9: 병렬 처리를 통한 성능 한계 돌파, 2026-02-22)

이번 버전에서는 웹 앱의 한계를 넘어 전문 오디오 배치 툴에 걸맞은 "속도"와 "반응성"을 확보하는 데 집중했습니다.

### A. 배치 처리 병렬 워커 풀 (Worker Pool) 도입
현재 순차적으로 처리되던 DSP 마스터링 및 MP3 인코딩 과정을 CPU 멀티 코어를 활용하도록 개편했습니다.
1. **`DSPWorkerClient` 및 `mp3.ts` 리팩터링**:
   - 단일 워커 인스턴스 대신 최대 4개(또는 하드웨어 코어 수)의 워커를 관리하는 풀 시스템을 구현했습니다.
   - 가용 워커가 있는 경우 즉시 할당하고, 없을 경우 큐(Queue)에 대기하는 메커니즘을 적용했습니다.
2. **트랙 처리 병렬화 (`QueueProvider`)**:
   - `Promise.all`과 Concurrency 제어를 통해 4곡을 동시 마스터링하도록 로직을 변경했습니다.
   - **결과**: 전체 대기 시간이 트랙 수에 비례하여 획기적으로 단축되었습니다.

### B. ZIP 압축 (`jszip`) Web Worker 전환
메인 스레드의 마지막 병목 지점이었던 ZIP 파일 생성 과정을 분리했습니다.
1. **`zip-worker.js` 및 `zip.ts` 구현**:
   - 수백 MB에 달하는 마스터링 결과물을 하나로 묶는 고부하 작업을 별도 스레드로 위임했습니다.
   - `jszip.min.js`를 워커 내에서 로드하여 압축을 수행하고, 실시간 진행률(0~100%)을 UI에 보고합니다.
2. **성능 효과**:
   - "Download All" 클릭 시 브라우저가 '응답 없음' 상태에 빠지던 문제를 해결했습니다. 압축 중에도 비주얼라이저가 부드럽게 작동합니다.

### C. 음원 메타데이터 보존 (MetaData Preservation) — ✅ 완전 해결
마스터링 후 곡 정보가 사라지는 문제를 해결하기 위해 데이터 보존 파이프라인을 구축하고, 발견된 3가지 호환성 이슈를 모두 수정했습니다.
1. **추출 로직**: `QueueProvider.tsx`에서 `music-metadata-browser`를 통해 메타데이터(제목, 아티스트, 앨범 아트 등)를 추출합니다. 업로드 시 백그라운드 프리캐시를 시도하고, 프로세싱 시점에서는 `await`로 추출 완료를 보장한 뒤 `TrackItem`에 저장합니다.
2. **주입 로직**:
   - **WAV**: `wav.ts`에서 RIFF LIST INFO 청크(UTF-8 텍스트)와 id3 청크(커버 아트)를 data 청크 뒤에 생성하여 주입합니다.
   - **MP3**: `mp3-tagger.ts` 유틸리티를 통해 ID3v2.3 태그(UTF-16LE, 커버 아트 APIC 포함)를 생성하고, Web Worker를 통해 데이터 최상단에 프리펜드(Prepend)합니다.
3. **해결한 호환성 이슈**:
   - **Buffer 폴리필**: `music-metadata-browser`가 Node.js `Buffer`를 내부 사용 → Vite 환경에서 `ReferenceError` 발생 → `main.tsx`에 `buffer` 패키지 글로벌 폴리필 적용.
   - **WAV 한글 메타데이터**: LIST INFO의 ASCII 전용 인코딩 → 한글이 `?`로 치환 → `TextEncoder` UTF-8 인코딩으로 교체.
   - **WAV 청크 순서**: LIST INFO를 data 앞에 배치하면 Windows Explorer가 인식하지 못함 → `fmt → data → LIST INFO → id3` 순서로 변경.

### D. 구조 정비 및 엔진 통합 (Core Consolidation)
외부 폴더에 의존하던 구조를 탈피하고 독립적인 프로젝트로 완성했습니다.
1. **루트 이관**: `mastermind` 소스 코드를 프로젝트 최상위(`Mastermind/`)로 전진 배치했습니다.
2. **엔진 복구 및 통합**: 유실되었던 DSP 엔진 라이브러리를 `src/lib/dsp` 경로로 복구하고 통합했습니다.
3. **독립적 빌드 구조**: 
   - `dspWorkerClient.ts`가 Vite의 워커 번들링 기능을 사용하도록 수정했습니다.
   - 이제 프로젝트는 외부 `web` 폴더 없이도 `src` 내부 소스만으로 완벽히 빌드 및 작동이 가능합니다.

### E. 글로벌 다국어 지원 (i18n) 구축
해외 사용자 비율 증가에 대비해 브라우저 언어 설정 기반의 동적 툴팁 번역 시스템을 도입했습니다.
1. **언어 자동 감지**: `useUiLocale.ts`를 통해 사용자 브라우저의 기본 언어를 자동 식별합니다.
2. **4개 국어 지원**: 한국어(ko), 영어(en), 포르투갈어(pt), 일본어(ja) 툴팁 번역을 `uiTips.ts`에 일괄 적용했으며, 비전문가도 이해할 수 있도록 직관적이고 친절한 톤 앤 매너로 일원화했습니다.

## 4. 현재 상태 및 향후 과제

### 현재 상태
- **성능**: 마스터링 및 인코딩, 압축까지 모든 CPU 집약적 작업이 워커에서 병렬로 진행됩니다. 웹 기반 오디오 툴 중 최상급의 처리 성능을 보여줍니다.
- **품질**: 병렬 처리 중에도 DSP 엔진의 무결성과 음질 순수성은 완벽하게 유지됩니다.
- **UI**: 어떤 무거운 배치 작업을 수행하더라도 60fps에 준하는 UI 반응성을 보장합니다.
- **메타데이터**: MP3/WAV 출력 모두에서 제목, 아티스트, 앨범 아트 등 원본 메타데이터가 완벽히 보존됩니다. 크로스 포맷(MP3→WAV, WAV→MP3)에서도 동작합니다.

### 향후 과제 (v1.0 예정)
1. **크롬 익스텐션(Chrome Extension) 포팅**:
   - 기존의 완전 클라이언트 사이드 작동 구조(Web Audio API + Web Worker)를 100% 활용하여 플러그인 형태의 접근성을 확보할 계획입니다.
   - 새 탭(New Tab) 실행 방식을 채택하여 넓은 작업 공간을 유지하면서, 웹스토어 노출면을 극대화합니다.
2. **배치 결과 리포트 UI**:
   - 모든 곡의 처리가 끝난 후, 각 곡의 LUFS 변동폭, 피크 값, 소요 시간 등을 한눈에 보여주는 요약 패널 및 결과 리포트 출력 기능. (후순위)

## 6. 개발 환경 특이사항 및 주의사항 (AI 가이드)

프로젝트 유지보수 시 AI 어시스턴트가 겪을 수 있는 반복적인 오류를 방지하기 위해 다음 사항을 권고합니다.

### ⚠️ 터미널 명령어 구분자 (PowerShell)
- **문제**: 현재 개발 환경은 Windows PowerShell을 사용하고 있으며, 명령어 연속 실행을 위한 `&&` 토큰을 지원하지 않는 구버전일 가능성이 높습니다.
- **해결**: 복합 명령어를 실행할 때는 `&&` 대신 세미콜론(`;`)을 사용해야 합니다.
  - **Bad**: `git add . && git commit -m "msg"`
  - **Good**: `git add . ; git commit -m "msg"`

### ⚠️ 빌드 도구 호환성 (Vite + Node 24)
- **문제**: Node v24.12.0 이상의 환경에서 `vite build` 실행 시 모듈 트랜스폼 단계에서 멈추거나 크래시되는 이슈가 있습니다.
- **해결**: 로컬 빌드 검증은 `tsc -b`로 수행하고, 실제 배포 빌드는 Node 20 LTS 환경을 사용하는 Vercel 등의 CI/CD를 활용하도록 합니다.

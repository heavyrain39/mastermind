# 마스터마인드 (Mastermind) v0.9 기획/현황서

## 1. 문서 목적
- 본 문서는 `마스터마인드` v0.9의 성능 최적화 작업 내역과, 현재의 기술적 성과 및 향후 남은 과제를 상세히 기록한 문서다.
- 배치 처리 성능을 극대화하기 위해 도입된 병렬 워커 풀(Worker Pool)과 ZIP 압축 워커화의 설계 의도를 명시하여 프로젝트의 기술적 자산을 보존한다.

---

## 2. 버전 히스토리 요약
- **`v0.7`**: DSP 오디오 코어 안정화 (위상/클리핑 수정), 출력 설정 UI 도입.
- **`v0.8`**: MP3 인코딩 워커 분리, 'None' 프리셋 도입, 진행바 UI 통합.
- **`v0.9` (Current)**: **배치 처리 병렬화 및 ZIP 압축 워커화 (성능 고도화).**
  - **성과**: 수십 곡 일괄 마스터링 시 처리 속도 약 2~4배 향상 (Multi-core 활용).
  - **성과**: 대용량 ZIP 생성 중 UI 프리징 현상 완전 해결.
  - **성과**: 워커 풀(Worker Pool) 시스템 구축을 통한 효율적 자원 관리.

## 3. 이번 작업 상세 (v0.9: 병렬 처리를 통한 성능 한계 돌파, 2026-02-22)

이번 버전에서는 웹 앱의 한계를 넘어 전문 오디오 배치 툴에 걸맞은 "속도"와 "반응성"을 확보하는 데 집중했습니다.

### A. 배치 처리 병렬 워커 풀 (Worker Pool) 도입
현재 순차적으로 처리되던 DSP 마스터링 및 MP3 인코딩 과정을 CPU 멀티 코어를 활용하도록 개편했습니다.
1. **`DSPWorkerClient` 및 `mp3.ts` 리팩터링**:
   - 단일 워커 인스턴스 대신 최대 4개(또는 하드웨어 코어 수)의 워커를 관리하는 풀 시스템을 구현했습니다.
   - 가용 워커가 있는 경우 즉시 할당하고, 없을 경우 큐(Queue)에 대기하는 메커니즘을 적용했습니다.
2. **트랙 처리 병렬화 (`QueueProvider`)**:
   - `Promise.all`과 Concurrency 제어를 통해 4곡을 동시 마스터링하도록 로직을 변경했습니다.
   - **결과**: 전체 대기 시간이 트랙 수에 비례하여 획기적으로 단축되었습니다.

### B. ZIP 압축 (`jszip`) Web Worker 전환
메인 스레드의 마지막 병목 지점이었던 ZIP 파일 생성 과정을 분리했습니다.
1. **`zip-worker.js` 및 `zip.ts` 구현**:
   - 수백 MB에 달하는 마스터링 결과물을 하나로 묶는 고부하 작업을 별도 스레드로 위임했습니다.
   - `jszip.min.js`를 워커 내에서 로드하여 압축을 수행하고, 실시간 진행률(0~100%)을 UI에 보고합니다.
2. **성능 효과**:
   - "Download All" 클릭 시 브라우저가 '응답 없음' 상태에 빠지던 문제를 해결했습니다. 압축 중에도 비주얼라이저가 부드럽게 작동합니다.

### C. 외과적 안정성 확보
- 기존의 복잡한 비동기 흐름을 망가뜨리지 않으면서도 병렬성을 주입하는 "외과적 리팩터링"을 수행했습니다.
- 취소(`Cancel`) 요청 시 가동 중인 모든 워커 작업이 안전하게 중단되도록 상태 제어를 강화했습니다.

## 4. 현재 상태 및 향후 과제

### 현재 상태
- **성능**: 마스터링 및 인코딩, 압축까지 모든 CPU 집약적 작업이 워커에서 병렬로 진행됩니다. 웹 기반 오디오 툴 중 최상급의 처리 성능을 보여줍니다.
- **품질**: 병렬 처리 중에도 DSP 엔진의 무결성과 음질 순수성은 완벽하게 유지됩니다.
- **UI**: 어떤 무거운 배치 작업을 수행하더라도 60fps에 준하는 UI 반응성을 보장합니다.

### 향후 과제 (v1.0 예정)
1. **오디오 메타데이터 보존 (ID3 Tag)**:
   - MP3 태그(Artist, Title) 및 앨범 아트를 결과 파일에 직접 기록하는 기능이 필요합니다. 현재는 오디오 정보만 보존되고 있습니다.
2. **배치 결과 리포트 UI**:
   - 모든 곡의 처리가 끝난 후, 각 곡의 LUFS 변동폭 등을 한눈에 보여주는 요약 패널 도입을 검토합니다.

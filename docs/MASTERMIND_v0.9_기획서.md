# 마스터마인드 (Mastermind) v0.9 기획/현황서

## 1. 문서 목적
- 본 문서는 `마스터마인드` v0.9의 성능 최적화 작업 내역과, 현재의 기술적 성과 및 향후 남은 과제를 상세히 기록한 문서다.
- 배치 처리 성능을 극대화하기 위해 도입된 병렬 워커 풀(Worker Pool)과 ZIP 압축 워커화의 설계 의도를 명시하여 프로젝트의 기술적 자산을 보존한다.

## 3. 이번 작업 상세 (v0.9: 병렬 처리를 통한 성능 한계 돌파, 2026-02-22)

이번 버전에서는 웹 앱의 한계를 넘어 전문 오디오 배치 툴에 걸맞은 "속도"와 "반응성"을 확보하는 데 집중했습니다.

### A. 배치 처리 병렬 워커 풀 (Worker Pool) 도입
현재 순차적으로 처리되던 DSP 마스터링 및 MP3 인코딩 과정을 CPU 멀티 코어를 활용하도록 개편했습니다.
1. **`DSPWorkerClient` 및 `mp3.ts` 리팩터링**:
   - 단일 워커 인스턴스 대신 최대 4개(또는 하드웨어 코어 수)의 워커를 관리하는 풀 시스템을 구현했습니다.
   - 가용 워커가 있는 경우 즉시 할당하고, 없을 경우 큐(Queue)에 대기하는 메커니즘을 적용했습니다.
2. **트랙 처리 병렬화 (`QueueProvider`)**:
   - `Promise.all`과 Concurrency 제어를 통해 4곡을 동시 마스터링하도록 로직을 변경했습니다.
   - **결과**: 전체 대기 시간이 트랙 수에 비례하여 획기적으로 단축되었습니다.

### B. ZIP 압축 (`jszip`) Web Worker 전환
메인 스레드의 마지막 병목 지점이었던 ZIP 파일 생성 과정을 분리했습니다.
1. **`zip-worker.js` 및 `zip.ts` 구현**:
   - 수백 MB에 달하는 마스터링 결과물을 하나로 묶는 고부하 작업을 별도 스레드로 위임했습니다.
   - `jszip.min.js`를 워커 내에서 로드하여 압축을 수행하고, 실시간 진행률(0~100%)을 UI에 보고합니다.
2. **성능 효과**:
   - "Download All" 클릭 시 브라우저가 '응답 없음' 상태에 빠지던 문제를 해결했습니다. 압축 중에도 비주얼라이저가 부드럽게 작동합니다.

### C. 음원 메타데이터 보존 (MetaData Preservation)
마스터링 후 곡 정보가 사라지는 문제를 해결하기 위해 데이터 보존 파이프라인을 구축했습니다.
1. **추출 로직**: `QueueProvider.tsx`에서 파일 업로드 시 비동기로 메타데이터(제목, 아티스트, 앨범 아트 등)를 추출하여 `TrackItem`에 저장합니다.
2. **주입 로직**:
   - **WAV**: `wav.ts`에서 RIFF LIST INFO 청크를 동적으로 생성하여 파일 끝에 주입합니다.
   - **MP3**: `mp3-tagger.ts` 유틸리티를 통해 ID3v2.3 태그를 생성하고, Web Worker를 통해 데이터 최상단에 프리펜드(Prepend)합니다.

### D. 구조 정비 및 클린업 (진행 중 중단)
구조를 단순화하기 위해 `Web-Audio-Mastering/mastermind`를 루트로 올리는 작업을 수행했습니다.
1. **성과**: 모든 정적 자산과 React 소스 코드를 `c:\Users\야차완\Desktop\Mastermind` 루트로 재배치했습니다.
2. **주의사항**: 이 과정에서 의존성 폴더인 `web/lib/dsp`와 `.git` 저장소가 함께 삭제되었습니다. 현재 프로젝트는 빌드 시 DSP 엔진 부재로 에러가 발생하며, 외부 백업을 통한 `dsp` 폴더 복구가 필수적인 상황입니다.

## 4. 현재 상태 및 향후 과제

### 현재 상태
- **성능**: 마스터링 및 인코딩, 압축까지 모든 CPU 집약적 작업이 워커에서 병렬로 진행됩니다. 웹 기반 오디오 툴 중 최상급의 처리 성능을 보여줍니다.
- **품질**: 병렬 처리 중에도 DSP 엔진의 무결성과 음질 순수성은 완벽하게 유지됩니다.
- **UI**: 어떤 무거운 배치 작업을 수행하더라도 60fps에 준하는 UI 반응성을 보장합니다.

### 향후 과제 (v1.0 예정)
1. **오디오 메타데이터 및 커버 이미지 보존 (ID3 Tag & Artwork)**:
   - **원본 데이터 추출**: 파일 업로드 시 `music-metadata-browser` 등을 활용해 아티스트명, 곡 제목, 앨범 아트(커버 이미지)를 메모리에 저장.
   - **태그 재주입(Re-injection)**: 마스터링 및 인코딩 완료 후, 최종 결과물(MP3/WAV)에 추출했던 메타데이터와 커버 이미지를 다시 박아넣는 로직 구현.
   - **결과**: 마스터링 후에도 모바일 앱이나 플레이어에서 곡 정보와 앨범 이미지가 그대로 유지되도록 함.
2. **배치 결과 리포트 UI**:
   - 모든 곡의 처리가 끝난 후, 각 곡의 LUFS 변동폭, 피크 값, 소요 시간 등을 한눈에 보여주는 요약 패널 및 결과 리포트 출력 기능.

## 6. 개발 환경 특이사항 및 주의사항 (AI 가이드)

프로젝트 유지보수 시 AI 어시스턴트가 겪을 수 있는 반복적인 오류를 방지하기 위해 다음 사항을 권고합니다.

### ⚠️ 터미널 명령어 구분자 (PowerShell)
- **문제**: 현재 개발 환경은 Windows PowerShell을 사용하고 있으며, 명령어 연속 실행을 위한 `&&` 토큰을 지원하지 않는 구버전일 가능성이 높습니다.
- **해결**: 복합 명령어를 실행할 때는 `&&` 대신 세미콜론(`;`)을 사용해야 합니다.
  - **Bad**: `git add . && git commit -m "msg"`
  - **Good**: `git add . ; git commit -m "msg"`

### ⚠️ 빌드 도구 호환성 (Vite + Node 24)
- **문제**: Node v24.12.0 이상의 환경에서 `vite build` 실행 시 모듈 트랜스폼 단계에서 멈추거나 크래시되는 이슈가 있습니다.
- **해결**: 로컬 빌드 검증은 `tsc -b`로 수행하고, 실제 배포 빌드는 Node 20 LTS 환경을 사용하는 Vercel 등의 CI/CD를 활용하도록 합니다.

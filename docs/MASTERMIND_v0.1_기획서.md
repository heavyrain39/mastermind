# 마스터마인드 (Mastermind) v0.1 기획서

## 1. 문서 목적
- 본 문서는 `마스터마인드`의 초기 제품 정의(v0.1) 문서다.
- 다음 작업자(LLM/개발자/디자이너)가 이 문서만 읽고도 다음을 즉시 이해할 수 있도록 작성한다.
  - 제품 컨셉과 사용자 목표
  - 현재 코드베이스 현황과 리스크
  - v0.1 범위, 구현 우선순위, 향후 확장 과제

---

## 2. 제품 한줄 정의
`JRPG/판타지 instrumental WAV 플레이리스트를 YouTube 환경에 맞춰 일관된 볼륨과 투명·따뜻·부드러운 톤으로 일괄 마스터링하는 로컬 웹앱`

---

## 3. 배경 및 사용자 목표
### 3.1 사용자 맥락
- 대상 오디오: JRPG/판타지 계열 instrumental 중심 WAV
- 일반 작업량: 1회당 약 18곡(최대 50곡) 배치 처리
- 목적:
  - 곡 간 볼륨 일관성 확보(YouTube 청취 환경 기준)
  - 과한 펀치/보컬 전면화 없이, 투명하고 따뜻하고 부드러운 결과
  - 개별곡/전체곡 모두 빠르게 A/B 비교 가능한 워크플로우

### 3.2 사운드 방향성 키워드
- 핵심: Transparent, Warm, Smooth, Clean
- 감성: 부드럽고 서정적이며 아름답고 약간 쓸쓸한 분위기
- 악기 특성: 오케스트라, 목관, 벨, 기타, muted drum, 신스 패드
- 불필요 요소:
  - 공격적 트랜지언트 강조
  - 보컬 존재감 부스팅(대상은 instrumental)
  - 비트 중심의 펀치 과장

---

## 4. 제품 형태 및 실행 방식
### 4.1 로컬 웹앱 가능 여부
- 가능하다.
- 권장 구조:
  - 프런트엔드: React 기반 웹앱
  - 로컬 실행: 더블클릭 가능한 Windows 런처(포터블)로 로컬 서버 기동 + 기본 브라우저 자동 오픈

### 4.2 더블클릭 실행 요구사항 반영
- 바탕화면/시작 메뉴에서 실행 파일(또는 바로가기) 더블클릭
- 자동으로 브라우저가 열리고 앱 진입
- 사용자 입장에서는 “설치형 느낌”에 가까운 로컬 웹앱 경험

### 4.3 장기 배포 확장성
- 아키텍처는 이후 GitHub + Vercel 공개 배포를 고려해 설계
- 로컬 전용 기능(파일 시스템 직접 쓰기 등)과 웹 공개 모드의 기능 차이를 명확히 분리

## 5. UX/UI 컨셉
### 5.1 디자인 원칙
- 미니멀, 플랫, 클린, 에디토리얼
- 불필요한 장식 최소화:

  - 그림자 남발
  - 호버 모션 과다

### 5.2 테마
- `Light / Dark / System` 3모드 지원
- 테마 전환은 즉시 반영
- 접근성 대비(텍스트/배경 명도 대비) 확보

### 5.3 레이아웃
- 모바일 대응은 v0.1 범위에서 제외(데스크톱 최적화)
- 좌우로 넓은 작업 화면 활용:
  - 좌측: 파일 큐/메타데이터/진행 상태
  - 중앙: 파형 및 A/B 플레이어
  - 우측: 마스터링 프로필/파라미터 패널

## 6. 핵심 기능 요구사항 (v0.1)
### 6.1 파일 입력/배치
- WAV 다중 업로드
- 일반 사용량(약 18곡) 쾌적 처리
- 최대 50곡 처리 가능
- 개별 곡 처리 및 전체 일괄 처리 모두 지원

### 6.2 마스터링 프로필
- 기본 프리셋: `JRPG Transparent Warm` (디폴트)
- 기본 권장값:
  - Target Loudness: YouTube 친화 기준(초기안 -14 LUFS)
  - True Peak Ceiling: 초기안 -1.0 dBTP
  - Stereo Width: 기본 105%
- 미세 조정 가능 파라미터 제공(범위 제한 포함)

### 6.3 A/B 비교 및 재생 UX
- 모든 곡에 대해 Before/After 즉시 A/B 비교 가능
- 한두 곡 샘플 비교가 아니라 “큐 전체 모든 곡” 대응
- 파형(waveform) 클릭 시 해당 지점 즉시 재생(seek)
- 원본/마스터 파형 동시 또는 토글 비교 표시

### 6.4 진행/결과 관리
- 곡별 진행 상태 + 전체 진행률 표시
- 처리 완료 후 곡별 결과 바로 청취 가능
- 출력 파일명 규칙 통일(예: `{원본명}_mastered.wav`)

## 7. 비기능 요구사항
### 7.1 성능
- 18곡 배치 작업 기준, UI 끊김 최소화
- DSP/인코딩은 워커 기반 오프메인 처리 우선
- 메모리 급증 방지를 위해 파일 단위 순차 처리 기본

### 7.2 안정성
- 곡 단위 에러 격리(1곡 실패가 전체 중단으로 이어지지 않게)
- 취소/재시도/실패 곡 재처리 지원(점진 도입)

### 7.3 품질 일관성
- 결과 loudness 편차 최소화
- 과도한 리미팅/왜곡 방지
- 악기 질감(목관/벨/패드)의 잔향과 섬세함 보존

## 8. 기술 방향 (초기안)
### 8.1 프런트엔드
- React + TypeScript + Vite
- 상태관리: 초기에 경량(React state + context), 필요 시 확장
- 파형 렌더링: 기존 `wavesurfer.js` 활용 가능

### 8.2 오디오 처리
- Web Audio API + Worker 기반 DSP 파이프라인
- 배치 렌더 엔진 분리:
  - 분석(측정) 단계
  - 마스터링 렌더 단계
  - 출력 인코딩 단계

### 8.3 로컬 실행/배포
- Windows 포터블 우선
- 옵션 A(권장): 경량 런처(로컬 서버 실행 + 브라우저 오픈)
- 옵션 B: Electron 유지/개선 후 BrowserWindow 대신 웹앱형 UX로 고정
- 장기: GitHub/Vercel 배포 모드 병행

## 12. 오디오 프로파일 제안 (JRPG Transparent Warm v0.1)
### 12.1 기본값(초기안)
- Target LUFS: -14
- True Peak Ceiling: -1.0 dBTP
- Stereo Width: 105%
- 저역 정리(과도하지 않게), de-harsh 완만 적용
- warmth/saturation는 미세량만 사용

### 12.2 튜닝 철학
- 선명도는 올리되 자극성은 억제
- 공간감은 유지하되 저역 중심은 흔들리지 않게
- 타격감보다 음색 정돈/질감 보존 우선

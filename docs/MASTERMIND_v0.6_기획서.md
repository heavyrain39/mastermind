# 마스터마인드 (Mastermind) v0.6 기획/현황서

## 1. 문서 목적
- 본 문서는 `마스터마인드`의 기획 목표, 구현 상세 내역 및 현재 개발 현황을 한눈에 파악할 수 있도록 작성된 기준 문서다.
- 이전 문서를 덮어쓰지 않고 각 버전을 보존함으로써 기획의 발전 과정을 추적하고, 새로운 작업자(LLM/개발자 등)가 투입되었을 때 개발 콘텍스트를 명확히 인계하는 역할을 한다.

---

## 2. 버전 히스토리
- **`v0.1`**: 제품 컨셉/사운드 방향 정의 및 배치 마스터링 범위 설정
- **`v0.2`**: React/TS/Vite 기반 3패널 UI 골격 구축, Queue/A-B 연동 1차 구현(상태 시뮬레이터)
- **`v0.3`**: 실제 DSP 워커 연동, 모노/에러 처리 보강 등 내부 프로세싱 기반 마련
- **`v0.4`**: UX 최적화(좌/중/우 정보 밀도 재편), Canvas 기반 웨이브폼 실 렌더 / 즉시 재생 기능 구현, 드롭다운 프리셋 및 결과 일괄 다운로드(ZIP) 도입
- **`v0.5`**: 전면적 UI/UX 고도화(에디토리얼+카세트퓨처리즘 интеграция), 독립적인 3D 비주얼라이저 결합, 유연한 CSS Grid 레이아웃 안착
- **`v0.6` (2026-02-21)**:
  - **프리셋 전문화 및 명칭 재정의**: 모든 프리셋에 고유한 오디오 파라미터 수치 부여
  - **다중 포맷 지원 엔진 게이트 개방**: MP3, M4A, AAC, OGG, FLAC 입력 허용
  - **프리셋 UX 개선**: 드롭다운 내 각 항목 및 트리거별 독립적인 좌측 플로팅 툴팁(ko/en) 동적 제공
  - **UI 버그 픽스**: 뷰포트 영역을 벗어나는 드롭다운 스크롤 이슈를 `position: fixed` 자동 방향 식별 알고리즘으로 해결

## 3. 핵심 제품 철학 및 목표 (유지)
### "The Clever Audio Mastering Ally"
> JRPG/판타지 계열의 Instrumental 플레이리스트를 YouTube 등 주요 플랫폼 환경에 맞춰, 일관된 볼륨(Loudness)과 맑은 톤(Warm & Clean Tone)으로 일괄 마스터링 해주는 순수 로컬 기반의 웹 앱이다.

- **대상/규모**: 한 번에 약 18곡 ~ 최대 50곡 배치 처리 (개인 작곡가/디자이너 타겟)
- **UX 철학**: 복잡한 플러그인을 숨기고 세련된 정밀 장비(카세트퓨처리즘)를 조작하듯 빠르고 직관적으로 전 곡을 A/B 비교 및 처리

## 4. 이번 작업 상세 (v0.6: 오디오 코어 및 프론트 정밀화, 2026-02-21)

이번 버전에서는 껍데기에 머물렀던 프리셋에 실제 영혼(수치)을 불어넣고, 사용자 편의를 위한 포맷 확장 및 세밀한 UI 조정을 단행했습니다.

### A. 마스터링 프리셋 차별화 및 재편
- 기존 단일 세팅값에 의존하던 6개 프리셋에 각각 고유한 `MasteringSettings` 파라미터 프로필(Target LUFS, Warmth, Clarity, Glue Compression 등)을 할당.
- **직관적 네이밍 변경**: 
  - `Velvet Lift` → `Warm Tape` (아날로그 테이프 질감 강조)
  - `Broadcast Calm` → `Loud & Clear` (유튜브 스트리밍용 고음압/고선명 목적 명시)
- **맥락 인지형 툴팁**: 일괄된 툴팁 대신, 드롭다운 메뉴를 열었을 때 각 프리셋 위에 마우스를 올리면 해당 프리셋의 성향을 차분하게 설명하는 좌측 플로팅 툴팁 구현.

### B. 입력 파일 포맷 전면 개방
- 브라우저 내장 `AudioContext`의 네이티브 디코딩 능력을 활용하여 업로드 허용 확장자를 극대화.
- `.wav`, `.mp3`, `.m4a`, `.aac`, `.ogg`, `.flac` 파일이 큐에 동시 진입 및 투명한 배경 변환 처리가 가능해짐.

### C. 드롭다운 오버플로우 및 레이아웃 한계 돌파
- 좁은 컨트롤 패널 내에서 드롭다운 메뉴 스크롤바가 생기는 현상(`overflow: hidden` 충돌)을 타파. 
- 메뉴 자체에 절대 화면 좌표계(`position: fixed`)와 뷰포트 하단 여백 감지 로직을 탑재하여 위/아래 방향을 스스로 결정해 열리도록 컴포넌트(`Dropdown.tsx`) 재설계.

## 5. 발견된 이슈 및 아키텍처 평가 (v0.6 척도)

전반적 아키텍처(`features` / `shared` / `lib` 분리), Web Worker 분리, 디자인 시스템의 일관성 등은 매우 훌륭한 수준이나, 실서비스로 도달하기 위해 보강할 약점들이 정리되었습니다.

### 🟡 현재 아쉬운 점 / 기술 부채
1. **결여된 테스트 코드**: 순환 로직(`sanitizeSettings`)이나 설정 변환(`toWorkerSettings`)에 대한 단위 테스트가 전무하여 향후 로직 리팩토링 시 회귀(Regression) 위험 존재.
2. **단순화된 파라미터 매핑**: `FullChainSettings` 변환 시, UI의 수치가 일부 단순 조건문(예: `addPunch: autoLevel >= 50`)으로 워커에 전달되어 미세한 프리셋 차이가 음질 결과물에서 충분히 발현될지 오디오 QA가 요구됨.
3. **거친 에러 핸들링**: 파일 디코딩 실패나 워커 크래시 시 사용자 친화적 메시지가 아닌 원시 Error.message 문자열이 그대로 표출됨.
4. **빌드 크래시 (Node 버전에 따른 Vite 에러)**: v0.2부터 지속 보고된 Node 24 종속성 이슈(`vite build transform error`). 개발버전 구동(`run dev`)과 프로덕션 코드는 문제없으나 빌드 컨테이너 환경을 LTS(20)로 강제할 필요가 있음.

## 6. 향후 과제 (남은 구현 목표)

### 1. 배치 처리 UX 극대화
- **전체 진행률 시각화**: 처리 중인 전체 곡들의 통합 진행 상태를 헤더나 큐 상단에 시각화하여 사용자의 대기 피로도 감소.
- **업로드 Lock**: 프로세싱 중에 추가 파일 업로드 시 발생할 수 있는 충돌을 방지하기 위해 업로드 버튼 비활성화 로직 도입.

### 2. 메타데이터 보존 로직
- **원본 정보 인계**: MP3/M4A/WAV 등에 포함된 ID3/비청각 메타데이터(아티스트, 앨범아트 등)가 마스터링 과정 후 최종 WAV/압축 산출물에도 최대한 이관되도록 보존 기법 검토 및 체크 옵션 신설.

### 3. 배포 환경 최적화
- **Vercel 호환성**: `favicon.png` 등 정적 리소스 경로가 Vercel 프로덕션 환경에서도 깨짐 없이 반영되도록 번들링 구조 점검.

# 마스터마인드 (Mastermind) v0.8 기획/현황서

- 본 문서는 `마스터마인드` v0.8의 인프라 고도화 작업 내역과, 현재 직면한 기술적 완성도 및 차기 과제를 상세히 기록한 문서다.
- 단순히 코드의 변경점을 나열하는 것을 넘어, 특정 기술적 선택(예: Web Worker 도입 등)을 하게 된 배경과 의도를 기술하여 프로젝트의 연속성을 확보한다.

## 3. 이번 작업 상세 (v0.8: 백그라운드 워커화 및 순수성 강화, 2026-02-22)

이번 버전에서는 서비스의 반응성(Responsiveness)을 전문 오디오 도구 수준으로 끌어올리고, 오디오 엔진의 "정직함"을 확보하는 데 집중했습니다.

### A. MP3 인코딩 Web Worker 분리 (UI Freeze 해결)
CPU 집약적인 MP3 변환 프로세스를 메인 스레드에서 완전히 분리했습니다.
1. **`mp3-worker.js` 구현**:
   - `lamejs` 라이브러리를 워커 내부에서 `importScripts`로 로드하여 독립적인 인코딩 환경을 구축했습니다.
   - Float32 to Int16 변환부터 실제 인코딩까지 워커에서 수행하며, 5% 단위로 진행률을 메인 스레드에 보고합니다.
2. **비동기 파이프라인**:
   - `mp3.ts`는 동기 함수 중심에서 `Promise<Blob>`을 반환하는 비동기 워커 클라이언트로 리팩터링되었습니다.
   - **결과**: 대용량 MP3 인코딩 중에도 스피너가 부드럽게 회전하며, 비주얼라이저/호버 등 모든 인터랙션이 쾌적하게 유지됩니다.

### B. 오디오 엔진의 순수성 강화: 'None' 프리셋 및 숨겨진 보정 제거
사용자의 의도를 100% 존중하는 '투명한' 마스터링 경로를 확보했습니다.
1. **'None' 프리셋 도입**:
   - 음원 보정(DSP)을 일절 수행하지 않고 목표 LUFS로 볼륨 정규화(Normalizing)와 리미팅(Peak Safety)만 수행하는 프리셋입니다.
2. **숨겨진 하드코딩 보정(`EQ_BASE`) 제거**:
   - 기존에 모든 프리셋에 공통적으로(사용자 모르게) 적용되던 미세 EQ 보정(고음역 부스트 등)을 완전히 삭제했습니다.
   - `None` 프리셋 한정으로 18kHz 로우패스 필터(LPF)까지 바이패스하도록 설계하여 원본 음질을 100% 보존합니다.

### C. UI/UX 레이아웃 최적화 (Progress UI)
1. **레이아웃 시프트(Layout Shift) 방지**:
   - 다운로드 중 버튼 내 퍼센티지 숫자가 노출되며 행 높이가 변하던 문제를 해결하기 위해 텍스트 수치를 제거했습니다.
2. **진행바 통합**:
   - 인코딩 진행률을 기존 트랙 행 하단의 `2px` 진행바에 재사용하여 시각적 일관성을 높였습니다. MP3 인코딩 중에는 진행바가 0%에서 100%까지 한 번 더 차오릅니다.

### D. 인프라 기반 강화: `lamejs` 로드 방식 최적화
- Vite 빌드 엔진(`esbuild`)의 특정 환경 크래시 문제를 방지하기 위해 `public/lib/lame.all.js` 직접 참조 방식을 유지하여 빌드 안정성을 확보했습니다.

## 4. 현재 상태 및 향후 과제

### 현재 상태
- **기능**: MP3/WAV 개별 및 배치(ZIP) 다운로드 기능이 안정적으로 동작합니다.
- **성능**: 인코딩 로직이 별도 스레드에서 돌기 때문에 멀티 코어 자원을 효율적으로 사용하며 웹 앱답지 않은 쾌적함을 보여줍니다.
- **품질**: 숨겨진 착색이 없어지면서 전문적인 "볼륨 정규화 도구"로서의 신뢰도가 상승했습니다.

### 향후 과제 (v0.9)
1. **ZIP 압축(`jszip`)의 Worker화**:
   - MP3 인코딩은 워커로 옮겼으나, 수십 개의 파일을 하나로 묶는 ZIP 압축 과정은 여전히 메인 스레드를 점유합니다. 거대 프로젝트 배치를 위해 이 작업도 워커로 분리해야 합니다.
2. **오디오 메타데이터 보존 (ID3 Tag)**:
   - MP3 태그(Artist, Title) 및 앨범 아트를 파일에 직접 기록하는 라이브러리 연동이 필요합니다.
3. **배치 처리 중 병렬 워커 최적화**:
   - 현재 시퀀셜하게 처리되는 인코딩 워커를 2~4개 병렬 가동하여 인코딩 속도를 한층 더 높이는 최적화 여지가 있습니다.

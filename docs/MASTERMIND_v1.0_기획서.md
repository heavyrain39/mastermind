- 기존 v0.9의 고성능 배치 처리(병렬 워커 풀, ZIP 압축 워커화) 기반 위에, 새롭게 추가된 **크롬 웹스토어 최적화 및 익스텐션 배포** 성과를 명시하여 프로젝트의 런칭 스펙을 기록한다.

## 3. 핵심 성과 (v0.9: 병렬 처리를 통한 성능 한계 돌파)

버전 1.0의 토대가 된 v0.9의 핵심 기술적 성과는 아래와 같습니다.

### A. 배치 처리 병렬 워커 풀 (Worker Pool) 도입
현재 순차적으로 처리되던 DSP 마스터링 및 MP3 인코딩 과정을 CPU 멀티 코어를 활용하도록 개편했습니다.
1. **`DSPWorkerClient` 및 `mp3.ts` 리팩터링**:
   - 단일 워커 인스턴스 대신 최대 4개(또는 하드웨어 코어 수)의 워커를 관리하는 풀 시스템을 구현했습니다.
   - 가용 워커가 있는 경우 즉시 할당하고, 없을 경우 큐(Queue)에 대기하는 메커니즘을 적용했습니다.
2. **트랙 처리 병렬화 (`QueueProvider`)**:
   - `Promise.all`과 Concurrency 제어를 통해 4곡을 동시 마스터링하도록 로직을 변경했습니다.
   - **결과**: 전체 대기 시간이 트랙 수에 비례하여 획기적으로 단축되었습니다.

### B. ZIP 압축 (`jszip`) Web Worker 전환
메인 스레드의 마지막 병목 지점이었던 ZIP 파일 생성 과정을 분리했습니다.
1. **`zip-worker.js` 및 `zip.ts` 구현**:
   - 수백 MB에 달하는 마스터링 결과물을 하나로 묶는 고부하 작업을 별도 스레드로 위임했습니다.
   - `jszip.min.js`를 워커 내에서 로드하여 압축을 수행하고, 실시간 진행률(0~100%)을 UI에 보고합니다.
2. **성능 효과**:
   - "Download All" 클릭 시 브라우저가 '응답 없음' 상태에 빠지던 문제를 해결했습니다. 압축 중에도 비주얼라이저가 부드럽게 작동합니다.

### C. 음원 메타데이터 보존 (MetaData Preservation)
마스터링 후 곡 정보가 사라지는 문제를 해결하기 위해 데이터 보존 파이프라인을 구축하고, 호환성 이슈를 해결했습니다.
1. **추출 로직**: `QueueProvider.tsx`에서 `music-metadata-browser`를 통해 메타데이터(제목, 아티스트, 앨범 아트 등)를 추출하고 유지 보장.
2. **주입 로직**:
   - **WAV**: `wav.ts`에서 RIFF LIST INFO 청크(UTF-8 텍스트)와 id3 청크(커버 아트) 주입.
   - **MP3**: ID3v2.3 태그(UTF-16LE, 커버 아트 APIC 포함) 데이터 최상단에 프리펜드(Prepend).

### D. 구조 정비 및 엔진 통합 (Core Consolidation)
외부 폴더에 의존하던 구조를 탈피하고 독립적인 프로젝트로 완성했습니다.
1. **루트 이관**: `mastermind` 소스 코드를 프로젝트 최상위(`Mastermind/`)로 전진 배치했습니다.
2. **엔진 복구 및 통합**: 유실되었던 DSP 엔진 라이브러리를 `src/lib/dsp` 경로로 복구하고 통합했습니다.
3. **독립적 빌드 구조**: `dspWorkerClient.ts`가 Vite의 워커 번들링 기능을 사용하도록 수정했습니다.

### E. 글로벌 다국어 지원 (i18n) 구축
1. **언어 자동 감지**: `useUiLocale.ts`를 통해 사용자 브라우저의 기본 언어를 자동 식별합니다.
2. **4개 국어 지원**: 한국어, 영어, 포르투갈어, 일본어 지원을 직관적이고 친절한 톤으로 일원화했습니다.

## 4. 이번 작업 상세 (v1.0: 크롬 익스텐션 포팅 및 배포, 2026-02-22)

v1.0에서는 안정화된 웹 앱을 기반으로 **기존 웹 배포 시스템(Vercel)을 침범하지 않고** 크롬 익스텐션을 완벽하게 이중 빌드할 수 있는 시스템을 구축하고 앱을 퍼블리싱했습니다.

### A. 듀얼 빌드 파이프라인 구축 (`vite.ext.config.ts`)
기존의 완전 클라이언트 사이드 작동 구조(Web Audio API + Web Worker)를 100% 활용하면서, 플러그인 폴더 격리에 성공했습니다.
1. **분리된 출력 경로**: 빌드 결과물을 Vercel의 `dist` 폴더와 분리된 `dist-ext` 로 지정했습니다.
2. **자동화 패키징 스크립트**: `package.json`에 `build:ext` 및 `zip:ext` 스크립트를 추가하여, 빌드부터 압축(`mastermind-ext-v0.8.0.zip` - 향후 버전 관리 기반)까지 명령어 하나로 자동화했습니다.
3. **상대경로 적용**: 익스텐션 환경 필수 조건인 에셋 경로 상대경로(`base: './'`) 설정을 적용했습니다.

### B. 프리셋 스프링 애니메이션 도입 (UX 향상)
- `framer-motion` 라이브러리를 활용하여 프리셋 변경 시 모든 슬라이더(게이지 및 핸들), 수치 텍스트가 물리 기반 모션(`stiffness: 1100`, `damping: 65`)으로 자연스럽게 전환되도록 개선했습니다.
- 사용자가 레인지 컨트롤을 직접 스와이프/드래그 시에는 애니메이션을 바이패스하도록 설계하여 직관적이고 즉각적인 조작감을 보장합니다.

### B. 익스텐션 코어 구성 및 UX 설계
익스텐션 환경에서 무거운 병렬 데이터 처리가 안정적으로 구동되도록 UX를 고도화했습니다.
1. **새 탭(New Tab) 실행 유도 (`background.ts`)**: 팝업창은 사용자가 화면 바깥을 클릭하면 곧바로 종료되는 치명적 한계가 있습니다. 마스터마인드는 클릭 시 `index.html`을 무조건 새 탭으로 열게 하여, 넓은 작업 공간과 100% 백그라운드 안정성을 확보했습니다.
2. **`manifest.json` 최적화**: Manifest V3 기준을 준수하며, `action` 설정만을 활용해 불필요한 권한 요청(Permissions)을 완벽히 제거했습니다. (No Remote Data Collection / Local Processing ONLY 명시)

### C. 퍼블리싱 및 자산 준비 완료
1. **다국어 및 개인정보처리**: 크롬 스토어 전용 퓨어 텍스트 기반 글로벌 영문 소개글과 개인정보처리방침(Privacy Policy)을 신설했습니다.
2. **스토어 에셋 확보**: Playwright 자동화 스크립트(`captureScreenshots.js`)를 구축하여 픽셀 매칭된 1280x800(Web Store 기본 뷰), 1400x900(프로모션 배너) 사이즈의 고해상도 UI 이미지를 자동 생성하는 툴킷을 갖췄습니다.
3. **제출 완료**: 크롬 개발자 대시보드 심사 제출을 선공적으로 마쳤습니다.

## 5. 현재 상태 및 향후 과제

### 현재 상태 (런칭 스펙)
- **성능**: 마스터링 및 인코딩, 압축까지 모든 작업이 워커에서 병렬 처리됨.
- **품질**: DSP 엔진 무결성, 6종 프리셋 제공, 유튜브(LUFS) 최적화 타겟 확보.
- **접근성**: Vercel 웹 접속 및 Chrome Extension 네이티브 플러그인 양방향 동시 지원 체제 확립.
- **프로모션 UX (2026-02-23 반영)**: 우측 컨트롤 패널 좌하단 CTA를 실행 환경에 따라 분기. 웹앱(`https://mstr-mnd.vercel.app/`)에서는 `Need focus? Try TAKT` / `Get Chrome Extension`, 익스텐션에서는 `Need focus? Try TAKT` / `Leave a review`를 50:50 확률로 노출.
- **메타데이터**: MP3/WAV 입출력간 커버아트 및 태그 100% 완벽 보존.

### 향후 과제 (v1.1 이후)
1. **배치 결과 리포트 UI**: 모든 곡의 처리가 끝난 후, 각 곡의 LUFS 변동폭, 피크 값, 소요 시간 등을 한눈에 보여주는 요약 패널 및 결과 리포트 출력 기능 추가.
2. **추가 포맷/샘플레이트 지원**: 사용자 피드백에 따른 추가 렌더링 옵션 확장.

## 6. 개발 환경 특이사항 및 주의사항 (AI 가이드)

### ⚠️ 터미널 명령어 구분자 (PowerShell)
- **문제**: 현재 개발 환경은 Windows PowerShell을 사용하므로 `&&` 토큰 대신 세미콜론(`;`)을 사용해야 합니다.
  - **Bad**: `git add . && git commit -m "msg"`
  - **Good**: `git add . ; git commit -m "msg"`

### ⚠️ 빌드 도구 호환성 (Vite + Node 24)
- **문제**: Node v24.12.0 이상의 환경에서 `vite build` 시 모듈 트랜스폼 크래시 이슈 존재.
- **해결**: 로컬 검증은 `tsc -b`, 웹 배포 빌드는 Node 20 LTS(Vercel) 환경 활용, 익스텐션용 로컬 빌드는 `npm run build:ext` 패키징 활용.
